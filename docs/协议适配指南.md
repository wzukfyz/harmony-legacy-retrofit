# 协议适配指南（新增设备 / 切换协议）

> 宣传要点：**适配一台新设备 = 新增一个 profile 文件；接入一种新协议 = 新增一个 protocol 实现文件。业务代码零改动。**

## 1. 架构分层

| 层 | 目录 | 职责 | 适配新东西时要动的地方 |
| --- | --- | --- | --- |
| 业务层 | `firmware/src/main.c` | 轮询 → 告警 → 上报 | 不改 |
| 协议层 | `firmware/src/protocol/` | 帧格式 / 校验 / 收发（现为 Modbus RTU） | 新协议：新增 `xxx.c` 实现 `ProtocolOps` |
| 设备层 | `firmware/src/device/profiles/` | 从站号、点位表（地址 / 缩放 / 阈值） | 新设备：复制模板填表 |

## 2. 新增设备（三步）

1. 复制 `firmware/src/device/profiles/profile_template.c/.h`，改名为 `profile_<设备名>.c/.h`；
2. 按设备手册填写点位表（`addr` 寄存器地址、`scale` 缩放、`alarm_max` 告警上限），
   全局变量命名为 `g_<设备名>Profile`；
3. `firmware/src/device/device_profile.c` 中按 `app_config.h` 宏返回新 profile
   （或直接替换当前宏分支）。

完成后 Clean → Build 即可，业务与协议代码无需改动。

## 3. 切换协议（示例：Modbus TCP）

1. 新增 `firmware/src/protocol/modbus_tcp.c/.h`，实现 `ProtocolOps`（init / read_regs）；
2. `firmware/src/main.c` 中的“协议切换点”改为 `&g_modbusTcpOps`；
3. `firmware/BUILD.gn` 的 sources 增加该文件。

## 4. 相关文件

- 设备点位事实源：`firmware/src/device/profiles/profile_demo.c`
- 人读映射表：`docs/寄存器映射表.md`
- PC 模拟器寄存器：`tools/config.yaml`

## 5. 当前验证基线

- 演示 profile 已通过 PC Modbus 从站 → USB-RS485 → MAX3485 → Hi3861/OpenHarmony → Wi-Fi/MQTT → 看板的实验室闭环。
- `python tools\modbus_sim\slave_rtu.py --interactive` 可在从站在线期间修改寄存器；使用 `alarm` / `normal` 演示阈值告警与恢复。
- `python tools\verify\verify_rs485.py` 自动验证三点位、告警及恢复；自动验收和交互从站不能同时占用 USB-RS485 串口。
- 当前温度、湿度与状态映射是演示基线，接入真实设备时仍须按设备手册核对站号、寄存器、缩放、阈值及通信参数。
