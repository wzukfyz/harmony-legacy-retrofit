# 普中-Hi3861开发板原理图文本化

> 来源：[普中-Hi3861开发板原理图.pdf](普中-Hi3861开发板原理图.pdf)，共 1 页。
> 本次按完整图像补齐所有红框模块；保留现有文件名，便于既有引用继续使用。
> 表格中的针脚编号为原理图符号编号，不代表实物排针的观察方向。接线前应确认丝印、1 脚位置和模块型号。

## 1. Hi3861 主控模块（U2）

U2 标注为 `Hi3861`，供电为 `VCC3.3`；图中模块引脚对应关系如下：

| U2 引脚 | 信号 / GPIO | 图中连接或别名 |
| --- | --- | --- |
| 1 | IO8 | P1 引出 |
| 2 | IO11 | P1 引出 |
| 3 | PWRON | RESET，连接复位电路 |
| 4 | IO14 | P1 引出 |
| 5 | IO13 | P1 引出 |
| 6 | IO12 | P1 引出 |
| 7 | IO9 | IIC_SCL，连接 NFC / OLED 时钟线 |
| 8 | VCC | VCC3.3 |
| 9 | NC | 未连接 |
| 10 | NC | 未连接 |
| 11 | NC | 未连接 |
| 12 | IO0 | P1 引出，本项目选作 UART1_TXD |
| 13 | IO1 | P1 引出，本项目选作 UART1_RXD |
| 14 | NC | 未连接 |
| 15 | GND | 地 |
| 16 | IO5 | SG1，舵机接口信号 |
| 17 | IO6 | SG2，舵机接口信号 |
| 18 | IO7 | P1 引出 |
| 19 | IO10 | IIC_SDA，连接 NFC / OLED 数据线 |
| 20 | IO2 | LED，板载指示灯 |
| 21 | IO4 | RXD_CPU，来自板载 USB 转串口电路 |
| 22 | IO3 | TXD_CPU，送往板载 USB 转串口电路 |

**编号区别**：U2 的 12/13 脚是模块上的 IO0/IO1；实际通过 P1 接线时，应找 P1 的 30/28 脚，不能混用两套编号。

## 2. IO 扩展排针（P1）

P1 为 `CON2*15`，双排 30 针。图中奇数针在左列、偶数针在右列。

| 左列针脚 | 网络 | 右列针脚 | 网络 |
| --- | --- | --- | --- |
| 1 | RELAY | 2 | R_ADC |
| 3 | BEEP | 4 | DS18B20 |
| 5 | MOTOR_IN4 | 6 | KEY2 |
| 7 | MOTOR_IN3 | 8 | KEY1 |
| 9 | MOTOR_IN2 | 10 | VCC3.3 |
| 11 | MOTOR_IN1 | 12 | VCC3.3 |
| 13 | GND | 14 | VCC3.3 |
| 15 | GND | 16 | VCC3.3（实物核验） |
| 17 | GND | 18 | IO2 |
| 19 | IO9 | 20 | IO10 |
| 21 | IO12 | 22 | IO7 |
| 23 | IO13 | 24 | IO6 |
| 25 | IO14 | 26 | IO5 |
| 27 | IO11 | 28 | IO1 |
| 29 | IO8 | 30 | IO0 |

- `RELAY`、`BEEP`、`MOTOR_INx`、`R_ADC`、`DS18B20`、`KEYx` 是**外设侧网络名**；不能据此推定它们已接到某个固定 GPIO。
- 图上未画出这些外设侧网络与特定 GPIO 的直接连线；使用时需核对实物跳线或连接方式。软件示例的 GPIO 选择不等于原理图中的固定连接。
- P1 第 13/15/17 脚为 GND；第 10/12/14 脚接 3.3V。用户已按实物核验第 16 脚也为 3.3V；原理图 PDF 的该脚标注与实物核验不一致，接线时以实板核对为准。
- P1 上未见 VCC5 引出；不要将其他接口的 5V 针误认为 P1 的 3.3V 针。

## 3. NFC 电路

- 芯片：U1，`NT3H1101W0FHKH`。
- 引脚：6=VCC、7=VOUT、2=VSS、5=SDA、3=SCL、1=LA、8=LB、4=FD。
- VCC 接 `VCC3.3`，VSS 接 GND；SDA/SCL 分别接 `IIC_SDA`/`IIC_SCL`，即 IO10/IO9。
- LA/LB 接 NFC 天线两端，C15（18nF）跨接在两条天线线上。
- 电源旁路电容：C1=10µF、C2=104（100nF）、C3=104（100nF）。
- VOUT 经 D1 指示灯与 R1（1kΩ）串联到 GND；图中未见 FD 继续引出到主控。

本页给出的是板载 NFC 芯片和天线连接，不包含射频布局、天线尺寸或调谐参数。

## 4. ADC 电路

- AD1 为标注 `103` 的电位器，按常见阻值编码对应 10kΩ。
- 电位器两端接 VCC3.3 / GND，滑动端为 `R_ADC`。
- `R_ADC` 引到 P1 的 2 脚；本图未指定它直接接到哪个 Hi3861 ADC 通道。

因此，采集该电位器前，应先确认 R_ADC 与目标 ADC GPIO 的实际连接，不能仅凭该模块名称选择 ADC 通道。

## 5. 复位电路

- RESET 网络接 U2 的 3 脚（PWRON）。
- R3（10kΩ）将 RESET 上拉到 VCC3.3。
- C4（10µF）接在 RESET 与 GND 之间。
- RST 按键按下时将 RESET 拉到 GND；正常松开时由上拉保持高电平。

图中未见 CH340 的 DTR/RTS 与 RESET 连线，不能由这张图认定板子支持串口自动复位。

## 6. DS18B20 / DHT11 接口（J2）

J2 共用同一组传感器接线，原理图将数据网络命名为 `DS18B20`：

| J2 引脚 | 信号 |
| --- | --- |
| 1 | VCC3.3 |
| 2 | DQ（DS18B20 网络） |
| 3 | NC |
| 4 | GND |

- DQ 经 R2（10kΩ）上拉到 VCC3.3，并引到 P1 的 4 脚。
- 本图未指定 DQ 直接接到哪个 GPIO，使用时需核对跳线连接。
- DS18B20 与 DHT11 的协议不同；共用接口不表示软件驱动可通用，也不表示可同时插接。

## 7. 蜂鸣器电路

- 元件：BZ1 蜂鸣器，R5=100Ω。
- 一端接 VCC5，另一端经 R5 接 `BEEP_OUT`。
- `BEEP_OUT` 来自 ULN2003D 的 11 脚，驱动输入 `BEEP` 接其 6 脚，并引到 P1 的 3 脚。

该电路通过 ULN2003D 下拉驱动蜂鸣器，不是由 MCU GPIO 直接承担蜂鸣器电流。图中未明确蜂鸣器为有源或无源型号。

## 8. 舵机接口（J1）

J1 为两路三线舵机接口：

| J1 引脚 | 信号 |
| --- | --- |
| 1 | SG1，接 IO5 |
| 2 | SG2，接 IO6 |
| 3 | VCC5 |
| 4 | VCC5 |
| 5 | GND |
| 6 | GND |

IO5/IO6 为信号端，舵机供电为 5V。若启用舵机功能，需要避免与这些 GPIO 的其他复用功能冲突。

## 9. IIC OLED 接口

| OLED 接口引脚 | 信号 |
| --- | --- |
| 1 | GND |
| 2 | VCC3.3 |
| 3 | IIC_SCL，接 IO9 |
| 4 | IIC_SDA，接 IO10 |

OLED 与 NFC 使用同一组 I²C 信号线；可否同时工作还需核对设备地址和各模块电气条件。本页未给出 OLED 的型号、地址及其内部电路。

## 10. 电源模块

- 稳压器：V1，`1117-3.3`，输入 VCC5，输出 VCC3.3。
- 引脚：3=IN、2/4=OUT、1=GND。
- 输入旁路：C5=104（100nF）；输出旁路：C6=10µF、C7=104（100nF）。
- DP1 为 3.3V 电源指示灯，经 R4（1kΩ）接 GND。
- USB1 的 VBUS 接 VCC5；板上舵机、蜂鸣器、继电器、电机驱动使用的 5V 电源与主控 3.3V 电源应区分。

本图未给出稳压器及各接口的可用输出电流，不能仅凭电源标号判断可同时带动多少外设。

## 11. 板载 LED

- 信号：`LED`，直接来自 U2 的 IO2（20 脚），也引到 P1 的 18 脚。
- 元件：D2 LED、R9（1kΩ），串联后接 GND。
- 按图中连接，LED 网络为高电平时点亮；它与 DP1 电源灯、D1 NFC 指示灯、DK1 继电器指示灯是不同电路。

## 12. 按键

- KEY1、KEY2 按下后分别将同名网络接到 GND。
- KEY1 引到 P1 的 8 脚，KEY2 引到 P1 的 6 脚。
- 本图未画出两条 KEY 网络的独立上拉电阻，也未指定其与某个 GPIO 的直接连接。

若通过跳线接入 GPIO，软件需按实际连接确认上拉方式；采用上拉后，通常以低电平表示按下。

## 13. 继电器电路

- 继电器：RK1，线圈由 VCC5 供电，另一端接 `RELAY_OUT`。
- 驱动：ULN2003D 的 7 脚输入接 `RELAY`，10 脚输出为 `RELAY_OUT`；RELAY 引到 P1 的 1 脚。
- DD1 在图中标注 `IN4148`（通常指 1N4148），跨在线圈两端作续流二极管。
- DK1 为红色指示灯，与 R10（1kΩ）串联后跨在线圈供电回路上。

| P2 引脚 | 触点 |
| --- | --- |
| 1 | NC，常闭 |
| 2 | COM，公共端 |
| 3 | NO，常开 |

线圈未吸合时 COM–NC 接通，吸合时 COM–NO 接通。ULN2003D 输入 RELAY 有效时，其输出下拉使线圈得电。

**注意命名**：继电器 COM 是触点公共端；它不同于 ULN2003D 的 COM 钳位端，也不同于电脑 COM 串口编号。

## 14. USB 转串口电路

- USB1 引脚：1=VBUS（VCC5）、2=D−、3=D+、4=NC、5=GND。
- U4 为 `CH340C`：1=GND、16=VCC（接 VCC5）、2=TXD、3=RXD、4=V3、5=UD+、6=UD−。
- USB D+/D− 分别接 CH340C 的 UD+/UD−；C9=104（100nF），C10=103（10nF）。
- Q1、Q2 均为 S8050，配合 R6/R8（4.7kΩ）及 R7/R11（2kΩ）构成串口接口电平转换电路。
- 主控发送路径：IO3 / TXD_CPU → Q1 电路 → CH340C RXD。
- 主控接收路径：CH340C TXD → Q2 电路 → RXD_CPU / IO4。

此电路是 **USB ↔ TTL UART**，不是 RS485；图中的 `R232` 是 CH340C 引脚名称，也不能据此认定板上有 RS232 电平收发器。

## 15. 电机与外设驱动（U3、J3）

U3 为 `ULN2003D`，提供七路达林顿下拉驱动：

| U3 输入脚 / 网络 | U3 输出脚 / 网络 |
| --- | --- |
| 1 / MOTOR_IN1 | 16 / OUT1 |
| 2 / MOTOR_IN2 | 15 / OUT2 |
| 3 / MOTOR_IN3 | 14 / OUT3 |
| 4 / MOTOR_IN4 | 13 / OUT4 |
| 5 / IN5（未见连接） | 12 / OUT5（未见连接） |
| 6 / BEEP | 11 / BEEP_OUT |
| 7 / RELAY | 10 / RELAY_OUT |

- U3 的 8 脚接 GND，9 脚 COM 接 VCC5；C8=104（100nF）。
- MOTOR_IN1～4 分别引到 P1 的 11/9/7/5 脚。
- J3：1=VCC5、2=OUT1、3=OUT2、4=OUT3、5=OUT4。

该接口适合匹配的四相驱动负载（例如常见五线步进电机）；图中未给出电机型号或额定电流。ULN2003D 是下拉驱动器，不是 RS485 收发器，也不是直流电机正反转 H 桥。

## 16. 本项目 UART / RS485 接线依据

原理图给出引出位置；UART1 复用关系由 SDK `hi_io.h` 确认（`HI_IO_FUNC_GPIO_0_UART1_TXD`、`HI_IO_FUNC_GPIO_1_UART1_RXD`）。两者应分开理解。

| 本项目用途 | GPIO / 网络 | 原理图引出位置 |
| --- | --- | --- |
| UART1 TX，接模块丝印 RXD（接收输入） | IO0 | P1 第 30 脚；对应 U2 第 12 脚 |
| UART1 RX，接模块丝印 TXD（发送输出） | IO1 | P1 第 28 脚；对应 U2 第 13 脚 |
| MAX3485 方向控制 EN | IO8 | P1 第 29 脚；已启用，实测高电平发送 |
| 3.3V 电源 | VCC3.3 | P1 第 10/12/14/16 脚（16 脚以实物核验为准） |
| 主控侧地 | GND | P1 第 13/15/17 脚，接模块左侧 GND |
| UART0 烧录 / 日志 | IO3 / IO4 | 板载 CH340C 路径，保留给 USB 串口 |

这张完整图中**未见 RS485 收发器或 A/B 差分接口**。完整通信链路为：

```text
PC USB-RS485 适配器 A/B
        ↕ RS485 总线
板端 TTL-RS485 收发模块 A/B
        ↕ RXD / TXD（模块 TTL 逻辑侧）
Hi3861 IO0 / IO1（UART1）
```

- 不要将 USB-RS485 适配器的 A/B 直接接到 IO0/IO1。
- 本项目使用手动方向 MAX3485 3.3V 模块：模块 TXD → IO1/UART1_RX，模块 RXD → IO0/UART1_TX，EN → IO8；EN 高发送、低接收已由 COM11 抓到的完整 Modbus 请求验证。
- 官方模块接线定义为左侧 GND/3V3 接主控，右侧 GND/A/B 接 USB-RS485 适配器对应端子；不要自行把两侧 GND 短接。
- 板端模块供电使用 3.3V，不接 5V。A/B 先按同名端连接；无应答时再检查适配器标注及总线极性。
- 接线时先断电，核对排针方向与地线，再连接信号；接好后再上电。原理图未包含隔离型 RS485 模块的内部连接方式。

## 17. 识图边界与更正

- 删除原文中的 `TXD H20` / `RXD H20` 和 `IIC3V3`：本页可确认的名称为 `TXD_CPU` / `RXD_CPU`、`VCC3.3`、`IIC_SDA`、`IIC_SCL`，不能保留 OCR 拼接出的名称作为接线依据。
- `104`/`103` 是常见电容编码，分别对应 100nF/10nF；AD1 的 `103` 按电阻编码对应 10kΩ。
- 本文覆盖全部红框模块，但没有补画原图不存在的线路，也没有将 BSP 示例选用的 GPIO 当成硬件固定映射。
- P1 实物方向与第 16 脚网络已由本项目实板核验；模块具体接口仍以官方引脚说明为准，本文记录本项目 MAX3485 接线与测试结果。
